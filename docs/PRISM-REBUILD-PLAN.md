# PRISM Rebuild Plan

## Phase 01 — Optimize
- Decouple camera inference from display cadence.
- Add frame backpressure and newest-frame-wins behavior.
- Cap mobile camera input.
- Pause hidden-page work.
- Keep low-tier compositor effects off.

## Phase 02 — Professionalize
- Centralize product identity and runtime constants.
- Make accessibility, focus, reduced-motion and mobile behavior first-class.
- Separate orchestration from the realtime engine.
- Keep exact project copy outside generated media.

## Phase 03 — Premiumise
- Establish one material language: dark optical glass, hairline edges, cold-white highlights, restrained cyan.
- Give motion a physical grammar instead of arbitrary easing.
- Make controls feel instrument-like and tactile.
- Treat typography as a precision layer.

## Phase 04 — Polish
- Remove visual noise before adding effects.
- Keep mobile compositor costs bounded.
- Use deterministic timing and cleanup.
- Give every transition a clear beginning, hero state, settle, and exit.

## Phase 05 — Cinematic intro
- Rebuild the intro from zero.
- Use generated cinematic footage as an optional visual substrate, never as the source of truth for text.
- Preserve a zero-network procedural fallback.
- Use a single scientific visual idea: one beam of light causes every scale transition.
- End with a physical dive through the prism into the live app.

## Phase 06 — Continuous quality
- Profile Android camera-on performance.
- Measure renderer draw calls, triangles, GPU frame time and inference latency.
- Add visibility-driven simulation budgets.
- Only increase fidelity where measurements show headroom.
